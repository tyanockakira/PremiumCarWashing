# PremiumCarWashing

Применяй эти правила к репозиторию PremiumCarWashing вместе с глобальным `AGENTS.md`. Здесь зафиксированы проектные контракты. Текущую ветку, состояние сервисов и результаты проверок определяй по фактам конкретной задачи.

## Архитектура и маршруты

- Это клиентское приложение React + Vite. `src/main.jsx` загружает глобальные стили, `src/App.jsx` содержит оболочку приложения и маршруты, `src/pages/` — экраны, `src/components/` — общие секции и элементы.
- Сохраняй публичные маршруты `/`, `/services`, `/pricing`, `/advantages`, `/contacts` и `/booking`, а также перенаправление неизвестных путей на `/`, пока задача явно не меняет этот контракт.
- Для внутренних переходов используй существующий React Router. Сохраняй ссылки из шапки, мобильного меню, футера и CTA, работу кнопок «Назад» и «Вперёд», переходы между страницами и возврат к началу нового экрана.
- При переходе из услуг и калькулятора цен сохраняй предварительный выбор через `location.state.service`. Прямой заход или перезагрузка `/booking` без этого состояния должны оставлять форму доступной с корректными значениями по умолчанию.
- Используй существующие компоненты, React Router, Motion и клиент Supabase. Новую библиотеку добавляй только при конкретном пробеле в текущем стеке и с учётом размера сборки.

## Визуальное направление и язык

- Сохраняй **Dark Premium Automotive**: почти чёрные и графитовые поверхности, сдержанный платиновый акцент, холодные оттенки, чёткая типографика и автомобильные изображения с понятной ролью.
- Бери цвета, шрифты, радиусы, тени и длительности переходов из `src/index.css`. Используй общие кнопки, контейнеры, `src/pages/PagesCommon.css` и SVG-иконки из `src/components/Icons.jsx`. Существующие алиасы `gold` не означают смену палитры на золотую.
- Избегай шаблонных ИИ-решений: декоративных бейджей без смысла, случайных градиентов, навязчивых свечений, повторяющихся карточек и нескольких конкурирующих акцентов. Используй SVG для интерфейсных иконок.
- Весь пользовательский интерфейс — на грамотном украинском, включая формы, ошибки, состояния загрузки и успеха, доступные имена, SEO и демонстрационные данные. Сохраняй `lang="uk"` в `index.html`.

## Адаптивность, доступность и движение

- Поддерживай узкие и широкие экраны без горизонтального переполнения и перекрытия контента. Проверяй длинные украинские подписи, мобильное меню, плавающие кнопки и формы на затронутых страницах.
- Сохраняй семантические ссылки, кнопки и поля, видимый фокус, подписи полей и понятные ошибки. При изменении меню или диалога проверь управление клавиатурой, закрытие и возврат фокуса.
- Анимации должны помогать ориентации или давать обратную связь. Сохраняй существующие переходы без добавления лишних циклов и эффектов. Для затронутых анимаций и программной прокрутки проверяй `prefers-reduced-motion` в CSS и JavaScript. В режиме сниженного движения контент и управление остаются доступны.
- Не ухудшай производительность ради декоративных эффектов или анимаций. Избегай неоправданного роста JavaScript-бандла и проверяй влияние правок, которые могут заметно увеличить его размер или нагрузку на браузер.

## Бронирование, демо и Supabase

- Сохраняй `src/lib/supabase.js` точкой настройки клиента, а `src/api/bookingApi.js` — границей запросов из интерфейса. Не дублируй RPC в компонентах. Учитывай контракты `submit_booking` и `submit_consultation`, а также локальные данные услуг и тарифов.
- Различай портфолио-витрину, имитацию отправки и реальную запись. Подключённый клиент может выполнять реальные запросы даже на странице с пометкой «демо». Успех демо-формы не должен обещать сохранение заявки, подтверждение визита или обратный звонок.
- При правках форм проверяй валидацию, ожидание ответа, защиту от повторной отправки, понятную ошибку и корректное подтверждение. Сетевую ошибку не подменяй успешным демо-ответом.
- Переменные `VITE_*` считай публичными. Во frontend допускаются URL проекта и публичный ключ Supabase. Не помещай туда `service_role`, приватные ключи или персональные данные для тестов.
- Не меняй схемы Supabase, RLS, RPC, переменные окружения или настройки Vercel без отдельного разрешения. Не запускай `supabase/schema.sql` и не отправляй тестовые заявки в production. Для проверки отправки используй демо, заглушку или согласованный dev-проект.

## Проверки

- `npm run lint` — для изменений JavaScript/JSX. `npm run build` — для изменений приложения, стилей, ресурсов, импорта или конфигурации сборки. Успешная сборка не подтверждает корректную работу интерфейса.
- Используй `npm run dev` для локальных сценариев и `npm run preview` для проверки собранного приложения. Подбирай проверки по области правки.
- При визуальных изменениях проверяй затронутый интерфейс в браузере на desktop и mobile.
- При изменениях маршрутов проверь прямой заход, перезагрузку вложенной страницы и переходы через меню. Если задача касается размещения, отдельно проверь, что окружение отдаёт SPA для допустимых вложенных маршрутов.
- При изменениях бронирования проверь переход из услуг и тарифов, прямой вход на `/booking`, успех в демо и отображение отказа. Перед отправкой в браузерном тесте убедись, что запрос перехватывается заглушкой, форма работает без реального клиента или используется согласованный dev-проект. Если это не подтверждено, останови проверку до отправки.

## Принципы дизайна PremiumWash 2.0

- Основное направление: Minimalist Automotive Editorial × Industrial Luxury.
- Приоритеты: функциональность, удобство, читаемость, визуальная простота, эстетика, анимации.
- Не перегружай интерфейс карточками, рамками, свечениями, градиентами, бейджами и декоративными иконками.
- Не дублируй кнопки, навигацию, информацию и пользовательские действия без функциональной необходимости.
- Используй типографику, качественные фотографии, свободное пространство, композицию и контраст как основные инструменты дизайна.
- Каждый элемент интерфейса должен иметь понятное функциональное назначение.
- Если удаление элемента не ухудшает функциональность, доступность или понимание интерфейса, рассмотри его удаление.
- Анимации должны быть плавными, осмысленными и поддерживать взаимодействие с интерфейсом.
- Избегай шаблонных AI-generated UI patterns и визуального нейрослопа.
- Сохраняй целостность фирменного стиля на всех страницах.
- Не жертвуй удобством, производительностью и доступностью ради визуальных эффектов.
